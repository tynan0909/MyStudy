GEMINI답변(팩토리패턴에대해)

**팩토리 패턴(Factory Pattern)**은 객체 지향 프로그래밍에서 가장 널리 사용되는 디자인 패턴 중 하나로, **객체를 생성하는 과정을 캡슐화(Encapsulation)**하여 사용하는 패턴입니다.

쉽게 말해, 객체를 직접 new 연산자를 사용하여 생성하는 것이 아니라, "공장(Factory)"이라는 별도의 클래스나 메서드에 객체 생성을 위임하는 방식입니다.

1. 핵심 개념: "왜 직접 만들지 않고 공장에 맡길까?"
보통 객체를 생성할 때는 구체적인 클래스에 의존하게 됩니다.

팩토리 패턴 미사용:

Java

// 사용자가 직접 피자를 만듦 (구체적인 클래스에 의존)
Pizza pizza = new CheesePizza();
이 방식은 CheesePizza라는 클래스 이름이 변경되거나 다른 피자로 바꾸려면 클라이언트 코드를 직접 수정해야 하므로 **결합도(Coupling)**가 높아집니다.

팩토리 패턴 사용:

Java

// 사용자는 공장에 주문만 함 (구체적인 클래스를 몰라도 됨)
Pizza pizza = pizzaFactory.createPizza("Cheese");
이제 클라이언트는 어떤 구체적인 클래스(CheesePizza)가 생성되는지 알 필요가 없습니다. 단지 "치즈 피자"를 달라고 요청할 뿐입니다.

2. 쉬운 비유: 카페 주문
카페에서 커피를 주문하는 상황을 상상해 보세요.

손님 (Client): "아이스 아메리카노 한 잔 주세요."라고 말합니다. (원두를 어떻게 갈고, 물 온도를 어떻게 맞추는지 알 필요가 없습니다.)

바리스타 (Factory): 주문을 받고 레시피에 따라 아메리카노를 **생성(제조)**합니다.

커피 (Product): 완성된 커피가 손님에게 전달됩니다.

여기서 바리스타가 바로 팩토리(Factory) 역할을 하며, 손님은 복잡한 제조 과정을 모르더라도 원하는 객체(커피)를 얻을 수 있습니다.

3. 주요 장점
결합도 감소 (Loose Coupling): 클라이언트 코드가 구체적인 클래스(예: SamsungTV, LgTV)에 직접 의존하지 않고, 인터페이스나 추상 클래스(예: TV)에만 의존하게 됩니다.

유지보수 용이성 (Open/Closed Principle): 새로운 제품(예: PotatoPizza)이 추가되더라도, 팩토리 내부의 로직만 수정하면 되고 클라이언트 코드는 건드릴 필요가 없습니다.

객체 생성 로직의 중앙 관리: 객체 생성에 필요한 복잡한 설정이나 과정을 한곳에서 관리할 수 있어 코드 중복이 줄어듭니다.

4. 구조 및 코드 예시 (Java 스타일 의사코드)
팩토리 패턴은 크게 Simple Factory, Factory Method, Abstract Factory로 나뉘지만, 가장 기본이 되는 개념은 아래와 같습니다.

1) 제품 인터페이스 (Product)
모든 제품이 공통으로 가져야 할 기능을 정의합니다.

Java

interface Shape {
    void draw();
}
2) 구체적인 제품들 (Concrete Products)
실제 생성될 객체들입니다.

Java

class Circle implements Shape {
    public void draw() { System.out.println("원 그리기"); }
}

class Rectangle implements Shape {
    public void draw() { System.out.println("직사각형 그리기"); }
}
3) 팩토리 클래스 (Factory)
객체 생성을 담당하는 공장입니다.

Java

class ShapeFactory {
    // 타입에 따라 알맞은 객체를 생성하여 반환
    public Shape getShape(String shapeType) {
        if (shapeType == null) return null;
        if (shapeType.equalsIgnoreCase("CIRCLE")) {
            return new Circle();
        } else if (shapeType.equalsIgnoreCase("RECTANGLE")) {
            return new Rectangle();
        }
        return null;
    }
}
4) 사용 (Client)
Java

public class Client {
    public static void main(String[] args) {
        ShapeFactory shapeFactory = new ShapeFactory();

        // 직접 'new Circle()'을 하지 않고 팩토리에 요청
        Shape shape1 = shapeFactory.getShape("CIRCLE");
        shape1.draw(); // 출력: 원 그리기
    }
}
5. 언제 사용해야 할까요?
생성해야 할 객체의 클래스를 컴파일 시점에 미리 알 수 없을 때.

객체 생성 과정이 복잡하거나, 생성 시점에 다양한 설정이 필요할 때.

라이브러리나 프레임워크를 개발할 때, 사용자가 내부 구현 클래스를 직접 다루지 않게 하고 싶을 때.

참고: 팩토리 패턴을 사용하면 클래스의 개수가 늘어나 코드가 다소 복잡해질 수 있다는 단점도 있습니다. 따라서 객체 생성이 매우 단순하다면 굳이 사용하지 않아도 됩니다.
